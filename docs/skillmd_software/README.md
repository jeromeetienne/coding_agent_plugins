# Skills as software packages

- Created: 16 November 2026
- Last updated: 16 November 2026
- Status: Maintained overview for people
- Related framing: [Agent instructions](../../AGENTS.md)
- Related issue: [Issue 82](https://github.com/jeromeetienne/coding_agent_plugins/issues/82)

For people developing and maintaining skills: which parts of the software lifecycle should a skill support, and how much structure is useful when a coding agent interprets the skill?

Jérôme Étienne proposes treating a skill as a software package. In this discussion, “SKILL.md” means the complete skill folder, including supporting documents and references. The discussion concerns capabilities of the complete skill, regardless of which file describes a capability.

Read [Discussion notes](discussion_notes.md) for the principles, the capability applicability table, Jérôme Étienne's responses, and the unresolved questions. Read [Skill classification](skill_classification.md) for the earlier proposal classifying the 16 skills by role, trigger, and authority.

These documents preserve a discussion. The applicability table is an assistant proposal for review, and the discussion has not established a new mandatory standard for every skill. The approach builds on [Coding in AI era](../coding_in_ai_era/README.md) and [the existing discussion notes](../coding_in_ai_era/discussion_notes.md).
